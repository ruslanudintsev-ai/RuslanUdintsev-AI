# Проверить портфолио за 5 минут — практическая PR/CI-демонстрация

**Небольшое воспроизводимое задание по управлению ИИ-агентами, а не инструмент для реального production.**

[Главная RU](../README.ru.md) · [English](TRY_IT.md) · [Исходники и ограничения](../examples/pr-evidence-gate/README.md) · [Доказательства](EVIDENCE_INDEX.ru.md)

## Что можно проверить самому

Координатор ИИ-разработки должен понимать, что **зелёные тесты — ещё не разрешение выпускать продукт**. В публичном AI-assisted примере на Python мы анализируем два **полностью вымышленных** JSON-снимка PR. Проверяем SHA, границы изменённых файлов, результаты обязательных CI и уведомления от самого автора комментария.

| Вымышленный пример | Условия | Ожидаемый результат |
| --- | --- | --- |
| `sample-approved.json` | Две успешные проверки, файлы в разрешённых каталогах, один собственный комментарий | `HUMAN_REVIEW_REQUIRED` — нужна приёмка владельца |
| `sample-blocked.json` | Посторонний файл деплоя и незаконченная проверка CI | `BLOCKED` — выпуск заблокирован |

Исходные данные — **локальные синтетические JSON-файлы**, а не выгрузка из живого GitHub. Здесь нет доступа к секретам, приватным репозиториям, реальным PR или платным моделям.

## Как запустить

Понадобится Python **3.12+**. В терминале выполни:

```bash
git clone https://github.com/ruslanudintsev-ai/RuslanUdintsev-AI.git
cd RuslanUdintsev-AI
python examples/pr-evidence-gate/triage.py --input examples/pr-evidence-gate/sample-approved.json
python examples/pr-evidence-gate/triage.py --input examples/pr-evidence-gate/sample-blocked.json
python -m unittest discover -s examples/pr-evidence-gate/tests -v
```

В первом отчёте ожидается **HUMAN_REVIEW_REQUIRED**, во втором — **BLOCKED**. Должны успешно пройти **13 модульных тестов**. Статус проверяй на **конкретном клонированном коммите**, а не по старому отчёту другого агента.

Можно также посмотреть [конфигурацию GitHub Actions](../.github/workflows/skills-check.yml) и [историю запусков](https://github.com/ruslanudintsev-ai/RuslanUdintsev-AI/actions/workflows/skills-check.yml). Зелёный CI не равен успешному production-релизу.

## Попробуй намеренно нарушить правило

В **локальной копии** открой `examples/pr-evidence-gate/sample-approved.json` и добавь в `changed_files` вымышленный путь `deployment/prod.yml`. Повтори первую команду — теперь должно получиться `BLOCKED`, потому что разрешены только `docs/` и `src/seo/`. Публиковать этот эксперимент в GitHub необязательно.

## Что это подтверждает

**Открытые доказательства:** исходники демонстрации, два искусственных примера, тесты, команды для повторения и история CI. Владелец поставил требования к проверке и предусмотрел обязательное решение человека.

**Не подтверждает:** безопасность настоящего PR, полноту реального CI, готовность к деплою, автоматическое устранение всех циклов ИИ-агентов, самостоятельное написание всего Python-кода владельцем или коммерческую эффективность.

## Как это применяется в реальной работе

Я определяю задачу и критерии приёмки, разделяю исполнителя и независимого проверяющего, требую результаты на точном GitHub SHA, обнаруживаю расхождения, организую исправления и сохраняю **окончательное право человека на слияние или деплой**.

Смотри [практику независимого ревью](INDEPENDENT_AGENT_REVIEW.ru.md) и [11 кейсов](../CASE_STUDIES.md). Приватные исходники и данные здесь не публикуются.

**Лучше показать работающий маленький пример, чем просто заявить о навыках.** Его можно изучить без регистрации на стороннем сервисе, оплаты и собеседования.
